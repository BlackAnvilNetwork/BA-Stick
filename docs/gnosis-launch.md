# Gnosis official launch runbook

**Dry-run note:** The 2026-10-12 deploy on chain 100 (`deployments/gnosis-dryrun.json`) was a dry-run mainnet launch. It wired **MockItems** and collapsed roles onto one EOA — do **not** treat it as production. A production server must **never** use that Checkpoint (open `setMinter` on MockItems). Official launch must use this runbook + the hardened `Deploy` script. The NETWORK=gnosis profile no longer auto-fills from that file.

## Dry-run MockItems (never for production)

| Fact | Detail |
|------|--------|
| File | `deployments/gnosis-dryrun.json` (`status: "dry-run-only"`) |
| Gap | `CharacterCheckpoint` points at **MockItems** (`contracts.MockItems`) — anyone can `setMinter` |
| Also wrong | Single EOA held admin + listing + fee + all roles |
| Server behavior | `applySettlementDeployFile` **refuses** to fill `LOK_NFT` / `LOK_FACTORY` / `LOK_CHECKPOINT` / … from a `dry-run-only` file unless `LOK_ALLOW_DRY_RUN_DEPLOY=1` (inspection only). `MockItems` is never copied into `LOK_ITEMS`. |
| Production path | Official `DeployChiado` + real `Items.sol` (or `ITEMS=0x0`), new deploy JSON without `dry-run-only`, set `LOK_DEPLOY_BLOCK`, then start the server |

Do not set `LOK_CHECKPOINT` / `LOK_ITEMS` by hand to the dry-run addresses. Do not run a public game against that Checkpoint.

Keys are **never** committed or generated by agents — addresses only in git. On chainid ≠ 31337 the launch path requires the Listing Safe to be distinct from the Admin Safe and from the Treasury Safe, and the Treasury Safe to be distinct from the Admin Safe. The Admin Safe holds emergency, guardian, rotator, and proposer. Its threshold stays at least 2. Mark Safes and Guild Wallets are created with the Safe Protocol Kit when the Mark comes online and when an accepted member opens a wallet. Their addresses are predicted before deploy. A Guild Wallet's owner is the member. The Mark, the listing key, and the session key are not owners of it.

## Ruleset proposal (48h timelock)

`RulesetRegistry` is initialized with **`minDelay = 48 hours`**.

1. The Admin Safe holds `PROPOSER_ROLE` and calls:
   `rulesets.propose(rulesetHash, delay, uri)` with `delay >= minDelay` (typically `48 hours`).
2. Wait until `activatesAt` (propose time + delay). Do **not** point production checkpoints at the hash before activation.
3. Engine wasm pin must match the proposed ruleset (see `LOCAL_RULESET_WASM_SHA256` / pin tests). For mainnet, propose a **new** hash bound to the audited wasm.
4. Admin Safe (DEFAULT_ADMIN_ROLE) can cancel a pending ruleset via `RulesetRegistry.cancel` (not the EMERGENCY role — L-3).

## Incident playbook

1. **Pause (GUARDIAN Safe)**  
   - `AhEscrow.pause()` — blocks `openAsk` / `buyAsk` (cancels still work).  
   - `CharacterFactory.pause()` — blocks `createCharacterFor`.  
   - Optional: `CharacterCheckpoint.pause()` / `revokeAllSigners()` if checkpoint abuse.
2. **Mass-cancel open asks** — LISTING key: `AhEscrow.cancelAsks(uint256[] ids)` (or server NFT-transfer / reconcile path). Do not leave asks buyable while paused for open.
3. **Listing Safe owner loss or compromise** — the owner is one key at threshold 1. Rotate that owner with `addOwner` / `removeOwner` on the same Listing Safe, then point `LOK_LISTING_KEY` at the new owner. The role address does not change. Never reuse the old key.
4. **Admin Safe owner compromise** — rotator and proposer are this Safe. Rotate by `addOwner` / `removeOwner` on the Safe. The role address does not change. The threshold stays at least 2.
5. **Stuck `openAsk` (mempool / pause revert)** — server stores pending hash+nonce under `open-ask-pending.json`. Ops: `POST /ops/replace-open-ask` with `Authorization: Bearer $LOK_OPS_STATUS_TOKEN` and JSON `{"listingId":"<id>"}` (fee-bumped same-nonce self-tx or cancelAsk). Or wait until the LISTING nonce advances, then reclaim/cancel on the log. Quarantined AskFilled fills: treasury refund procedure (document the fill listingId + buyer tx on the ops channel; Safe sends xDAI to buyer).
6. **Upgrade / setMinDelay** — only via TimelockController (`upgradeAuthority`); never set `minDelay` below 1 day. On chain 100, `TIMELOCK` is required at deploy.
7. **Unpause** — DEFAULT_ADMIN Safe after the incident is contained (`unpause` on AhEscrow / Factory).

## Post-deploy checklist

1. Roles: Admin Safe holds admin, emergency, guardian, rotator, and proposer. Listing Safe holds the listing role. Treasury Safe is `feeRecipient` and is not the Admin Safe. Deployer admin and listing roles are dropped. Admin Safe threshold is at least 2.
2. `factory.setStartingJob(job, true)` for each starting job.
3. Items: `MINTER_ROLE` → checkpoint; `setItems`; register launch slugs (if `ITEMS != 0`).
4. Ruleset propose + 48h wait.
5. Sourcify/Blockscout green on all four impls + AhEscrow (+ Items).
6. Fund the Listing Safe owner with minimal xDAI for gas. Sweep leftovers to the Treasury Safe after ops.
7. Server: copy `apps/server/.env.gnosis.example` → `.env.local` (`NETWORK=gnosis`, `LOK_LISTING_KEY`, `LOK_DEPLOY_BLOCK`). Blank `LOK_NFT`/`LOK_FACTORY`/`LOK_AH_ESCROW` fill from deploy JSON **only after official deploy** — never the dry-run MockItems Checkpoint. Web: `VITE_WALLETCONNECT_PROJECT_ID` + `VITE_NETWORK=gnosis` (or `VITE_CHAIN_ID=100`).
8. Confirmations: profile default **30** blocks (~2.5m) on Gnosis/Chiado; watchers prefer `eth_getBlockByNumber("finalized")` when the RPC supports it (`LOK_USE_FINALIZED=0` to disable). Override with `LOK_CONFIRMATIONS`. RPC fallbacks: `LOK_CHAIN_RPC_URLS`.

### Where `LOK_LISTING_KEY` goes

`LOK_LISTING_KEY` is the owner key of the Listing Safe. That Safe holds AhEscrow `LISTING_ROLE` and PvpBounty `OPERATOR_ROLE`. The key pays gas. It is not the role address. **Never** put `LOK_OWNER_KEY` / admin `0x08cD…` on the server — production boot refuses those vars.

| Host | Set the key here |
|------|------------------|
| Local / laptop Gnosis | `apps/server/.env.local` → `LOK_LISTING_KEY=0x…` (gitignored; copy from `.env.gnosis.example`) |
| Production Node process | Process env for `apps/server` on **PORT 8787** — host secret panel, systemd `EnvironmentFile`, Docker/K8s secret, etc. Same name: `LOK_LISTING_KEY` |

No forge/CI deploy target for the game server is checked into this repo. If the Listing Safe owner key is lost or compromised, rotate the owner on that same Listing Safe. `LISTING_ROLE` and `OPERATOR_ROLE` stay on it. The role address does not change.

## Ops (production server)

| Probe | URL | Meaning |
|-------|-----|---------|
| Liveness | `GET /health` | Process up (always 200 when listening) |
| Readiness | `GET /ready` | Lok data dir open; RPC not stuck in hard fail |
| Status | `GET /status` | JSON: network, **redacted** RPC hosts, watcher lags, dropped-cancel + quarantine counts, recent structured alerts |
| Replace stuck openAsk | `POST /ops/replace-open-ask` | Body `{"listingId":"…"}`; fee-bumped same-nonce replace or cancelAsk (same auth as `/status`) |

Same `PORT` as the WebSocket game server (default `8787`).

**`/status` / ops auth:** socket `remoteAddress` only (never `Host` / forwarded headers). On Gnosis/Chiado (`NETWORK=gnosis|chiado` / chain 100|10200), `LOK_OPS_STATUS_TOKEN` is **required** and only `Authorization: Bearer …` is accepted (loopback bypass off — same-host reverse proxies look local). Dev/anvil: loopback or bearer. RPC URLs are scheme+host; `dataDir` is basename only; BigInt tip/cursors serialize as strings. Ops error bodies scrub full RPC URLs.

**Structured alerts** — stderr JSON lines (`event`: `watcher_lag`, `nft_transfer_cancel_dropped`, `ask_filled_quarantine`). Lag threshold: `LOK_WATCHER_LAG_ALERT_BLOCKS` (default 50). Durable files under `LOK_DATA_DIR`:

- `nft-transfer-cancel-dropped.json`
- `lok-ask-filled-quarantine.json`

**Backups** (cron recommended, e.g. hourly):

```bash
cd apps/server
LOK_DATA_DIR=./data BACKUP_ROOT=./backups RETAIN=48 ./scripts/backup-data-dir.sh
```

Keys are never in the data dir — only rotate/sweep EOAs separately.
